# 00. Исходный контекст и границы

## Цель

Уменьшить ручную работу оператора при публикации полного образа диска на
клиентские станции, сохранив управляемость, наблюдаемость и возможность
безопасного отката для каждой станции.

## Главный сценарий MVP

1. Оператор регистрирует любое количество станций и агентов.
2. Агенты сообщают heartbeat, процессы и доступность `D:`; оператор подтверждает готовность полного диска к публикации.
3. Оператор создаёт draft publish job и выбирает станции.
4. Система выполняет preflight клиентов; admin station, если используется, остаётся optional.
5. Оператор явно подтверждает готовность клиентов к смене полного диска.
6. Mock или согласованный TrueNAS adapter создаёт snapshot исходного dataset и отдельные clone для выбранных станций.
7. Worker переключает станции с независимым прогрессом.
8. Каждая станция отдельно проходит verify.
9. Ошибочная станция сохраняет старую рабочую версию и может быть откатана отдельно.

## Что не входит в первый безопасный срез

- Автоматическое завершение процессов.
- Автоматическое удаление zvol, snapshot, clone или extent.
- Управление iSCSI со стороны Windows-агента.
- Хранение TrueNAS API key на станции или в браузере.
- Поддержка горячего switch по умолчанию.
- Подключение к реальному NAS без отдельного согласования и интеграционного gate.
- Неограниченное изменение схемы TrueNAS «на глаз» по аналогии с REST API.

## Роли компонентов

| Компонент | Отвечает | Не отвечает |
|---|---|---|
| Frontend | Выбор, отображение, подтверждения, события | TrueNAS, секреты, бизнес-решения без backend-проверки |
| API | Auth, валидация, команды, read-model, переходы workflow | Долгие storage-операции в HTTP-процессе |
| Worker | Durable выполнение, retry, прогресс, компенсационные состояния | UI и прямое доверие browser-параметрам |
| PostgreSQL | Источник состояния, аудит, идемпотентность, блокировки | Хранение больших process snapshots навсегда без retention |
| Redis | Очередь/события/координация по выбранному worker | Единственный источник истины для job |
| Windows-агент | Heartbeat и наблюдение за локальным ПК | TrueNAS key, iSCSI switch, принудительное закрытие |
| TrueNAS adapter | Versioned transport и безопасные разрешённые операции | Процессная проверка Windows и UI |

## Нефункциональные требования

- Повторяемость: повтор запроса не должен создавать дубликаты master snapshot или clone.
- Наблюдаемость: у каждого опасного действия есть job ID, station ID, timestamp, результат и audit event.
- Частичный успех: сбой одной станции не скрывает результат других и не запускает разрушительный cleanup.
- Свежесть: stale/offline отделяются от здорового состояния; устаревший зелёный флаг недопустим.
- Тестируемость: mock TrueNAS позволяет пройти workflow без сети и NAS.
- Ограничение blast radius: операции выполняются только над явно выбранными станциями и проверенными mapping.

## Словарь

- **Station** — зарегистрированный физический или логический клиентский/админский ПК.
- **Agent** — процесс-служба на Windows, принадлежащий станции.
- **Source dataset** — исходный TrueNAS dataset полного диска, например `games/master-games`.
- **Master snapshot** — зафиксированный snapshot source dataset для одной публикации.
- **Storage clone** — новый dataset/zvol, созданный из master snapshot для клиента.
- **Target/extent mapping** — соответствие iSCSI target станции и backing extent/zvol.
- **Preflight** — набор проверок перед публикацией и переключением.
- **Freshness** — допустимый возраст heartbeat/process/drive snapshot.
- **Hot switch** — переключение mapping без гарантии, что Windows и игра полностью idle; feature flag, выключенный по умолчанию.
